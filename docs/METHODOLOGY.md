# 方法与证据边界

版本：0.1.0 / 2026-10-11。

## 要回答的问题

在明确的模型映射、请求协议和参数下，候选端点能否完成一组可复现任务？相对用户指定参考端点，观察到了怎样的能力与可用性差异？

这和“服务商是否故意欺骗”“实际权重是哪一款模型”“全站有多少比例的流量被降级”是不同问题。0.1.0 只实现前一组问题。

## 操作步骤

1. 固定代码版本、题目生成器版本和 seed。先核验本地答案生成逻辑。
2. 指定候选与参考端点，并记录模型快照或别名的映射依据。参考端点不是自动被认证的“官方”。
3. 让协议、输出上限、采样与推理参数尽量一致。无权限观察上游隐藏提示、路由与量化时，明确记录未知条件。
4. 在开始前固定预算及覆盖范围，执行 `plan`。费用估算需要实际 token 与服务商规则；字符数只是请求规模提示。
5. 将题目按 seed 打乱，每道题轮换端点调用顺序。每题为一次全新会话；并发、历史对话和客户端 Agent 不参与本版测试。
6. 保存逐请求时间、摘要、允许的响应字段和计分结果。错误不自动重试或静默更换参数。
7. 区分回答计分、接口错误和同题配对比较。启用 `--save-responses` 后可以检查已保存文本；不启用时只能核对生成器和重新请求。
8. 如果发现差异，改变一个条件重新测试，例如输出预算，保留两份报告。不要用新报告覆盖旧报告。

## 为什么不直接问“你是什么模型”

身份自述与 `model` 字段都由被测服务输出，网关或提示词可以影响它们。它们可作为元数据，不是独立的模型身份担保。本版演示故意让两个不同表现的模拟端点使用完全相同模型标签。

能力测试只能建立行为证据。推理预算、模型版本、服务商系统提示、缓存、上下文加工、参数转换和网络状况都可能造成差异。因此不把几道题答错直接写为“掉包实锤”。

行为指纹则比较模型在特定采样协议下的响应分布与条件匹配的参考分布。这需要自变异校准、同模型阴性对照和不同模型阳性对照。0.1.0 **没有**实现指纹识别算法，也没有借用别人的准确率或阈值。

## 统计解释

目前只有次数、通过数、中位响应耗时和同题配对通过率差。没有假设检验、置信区间或自动因果归因。

- 多次生成相似模板的数据，不等于从真实编程任务分布独立采样。单纯增加题量不能自动变成可信的身份鉴定。
- 两端都能评分的样本才进入配对差；一侧报错的任务会被排除，存在幸存应答偏差。接口错误应与配对分数一并阅读。
- 题型简单时，很多模型均可满分；满分没有型号辨识力。
- 公开题型可以被测试识别路由绕过。随机 seed 只能更换数据，不能保证题型隐蔽。
- 单次测试无法证明之后、别的用户、其他时段的请求也采用相同路由。
- “未发现差异”没有证明“没有掺水”。观察到差异也没有独立证明运营者意图。

## 下一阶段的有效性验证

| 场景 | 已知真值 | 需要观察 |
|---|---|---|
| 官方同快照，对自身重复 | 未发生替换 | 误报与自然波动 |
| 同模型，不同采样/输出预算 | 条件变化 | 参数敏感性与误判风险 |
| 已知不同模型作候选 | 确实换模型 | 漏报与判别力 |
| 受控关闭思考 | 能力配置变化 | 不能混称权重替换 |
| 受控删除上下文中段 | 请求加工 | 位置与长度效应 |
| 受控混合路由 | 已知替换比例 | 样本量、时段和漏检关系 |
| 错误/限流注入 | 服务不可用 | 不应归因为模型身份 |

这些都是**未来校准项目**，不代表目前已有实验数据。本版唯一已知真值对照是明确标注的 Mock。

## 不采用的证据捷径

不采集或索要模型隐藏思维链；不将广告文案、拒绝回答风格或速度变化单独用作身份判据；不把随机生成的总分叫作“模型纯度”；不直接用另一个大模型当唯一裁判；不将不可信生成代码放在主机上执行。
